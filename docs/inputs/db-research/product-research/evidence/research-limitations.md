# Research limitations and unverified assumptions

Research date: **8 October 2026**. This is a product discovery and architecture study. It creates no platform implementation, deploys no candidate, changes no existing POC, and creates no production or lab database connection. All proposed capabilities remain **DESIGN_PROPOSAL / NOT_TESTED**.

## Evidence boundaries

- The 220 catalog entries are granular proposed capabilities, including optional and rejected scope. The 112 BASELINE entries are Bytebase-inspired references, not 112 verified Community features. API messages, routes, table declarations and plan flags establish only the stated source surface. They do not establish complete behavior, authorization, edition entitlement or Oracle correctness.
- The baseline uses the retained Bytebase snapshot `80524fc54601bcc5545575e02f83b23ee6bb0a70`. Eight selected files at observed current head `16b89d9b49741c65623970038859d0d6397c8fe5` were byte-identical. Other frozen paths were inspected at the historical pin; equality of the whole repository or current release is **UNKNOWN**. The exact source scopes accompany each reference.
- The source survey covers relevant APIs, navigation, metadata, permission/gate paths and execution mechanisms. It is extensive but does not prove exhaustive discovery of every feature, engine, cloud edition or release. NOT_FOUND_IN_REVIEW means absent from the reviewed paths, not proven absent everywhere. DIFFERENTIATOR identifies a proposed improvement, not exclusive novelty across all competitors.
- Source/code observations and retained exact-build POC results are separate. Historical Bytebase FREE observations do not certify present Enterprise behavior. Historical ODC execution does not establish a Git version/checksum ledger. Archery source and local executor probes do not constitute live Oracle acceptance; its real Oracle criteria remain NOT_RUN. No historical runtime success transfers to this new platform.
- Eleven local snapshot records, 181 source references, dated primary documentation and 22 selected current-file hash records support the findings. Existing source snapshots are reused without modification. Newly retrieved upstream files were inspected in a temporary cache outside this repository; their full contents are not vendored here. Pinned URLs and SHA-256 records support repeat retrieval, but future network availability is not guaranteed. The validator can optionally re-fetch those exact selected files; its offline mode checks their register consistency only.
- Official documentation is live and may change. The document registry records retrieval date and bounded claims rather than frozen website copies. Some old/new Bytebase release/file-organization documentation URLs were inaccessible. Release ingestion findings use pinned API/action source instead. The HA documentation reference records only the advertised index description; complete HA operation on a particular edition/build is **UNKNOWN / NOT_TESTED**.
- UI research uses existing screenshots, source navigation and documented workflows. It includes no new interactive browser walkthrough or user testing. Fourteen proposed screen contracts and Mermaid flows are design artifacts; they are not rendered application screens, copied vendor assets or proven usability improvements.

## Architecture gates

The preferred TypeScript/Fastify + node-oracledb Thin stack is conditional. Driver 7.0.1 source/license was inspected, but this study did not run it against 19c/21c, RAC/service aliases, TCPS, quoted owners, proxy credentials, failover, cancellation or network loss. Required authentication/transport and dictionary grants must be confirmed with the estate DBA. Thin support must not be inferred from Thick capabilities. An estate that mandates unsupported transport/authentication reopens the driver decision.

The Apache Flyway parser-only JVM helper is an **unimplemented integration proposal**. No supported standalone parser API or ready adapter is asserted. Isolating its internal parser, dependency closure, precise source ranges and statement bytes without JDBC or proprietary bundles needs a feasibility harness. Internal API churn, packaging and incompatible Oracle syntax may make it unsuitable. Do not substitute a naive semicolon splitter or an unreviewed custom grammar if this gate fails; reopen the decision.

The hybrid ledger, same-session DBMS_LOCK cover package and recovery protocol are proposed contracts. They need privileged bootstrap review and actual 19c/21c failure injection. Documentation supports DDL implicit commits and session lock semantics; it does not prove this coordinator. Arbitrary DDL cannot be atomically committed with target receipts and central metadata. Commit/receipt gaps, orphan sessions and restore disagreement therefore remain explicit HOLD cases, with no exactly-once or release-wide rollback claim.

Validity checks require sufficient owner/type-specific catalog visibility and explicit expected-object/postcondition manifests. A driver call returning without exception, an empty USER_ERRORS result under the wrong login, or an APPLIED receipt alone cannot establish success. Baseline inventories and dependency checks cannot prove every application behavior or discover every externally changed object.

Immutable approval, segregation of duties, promotion, permissions and crash recovery have been designed but not implemented or security tested. The end-to-end milestone must test alternate API/worker/CI entry points, concurrent admissions, approval invalidation and authorized reconciliation.

## Product, effort and licensing limits

- The 50-service/500-schema/20-user values are initial requirements, not achieved benchmarks or license quotas. Queue concurrency, latency budgets and artifact limits are proposed configurable defaults. No throughput, availability, recovery time or storage benchmark was run.
- The 110–170 engineer-week MVP estimate is a planning range for ten shared packages, with 4–5 engineers, DBA/security participation and 25% coordination/support allowance. It is not a delivery commitment. Team expertise, estate authentication, parser feasibility, offline dependency mirrors and review turnaround can materially change it. Per-feature complexity estimates are not additive.
- Local invite-only authentication is a reversible MVP assumption. An established on-prem OIDC provider may be substituted during the first implementation phase. No actual IdP, GitLab version, Jenkins security model, secrets service or cluster distribution was configured or surveyed.
- Proposing Apache-2.0 does not change this repository's existing license or grant rights in other products. Source license, commercial enablement, distributed binaries, Oracle database/client terms, transitive dependencies and assets have different scopes. No complete future SBOM, legal certification, advisory scan, offline build or notice bundle exists yet.
- Flyway public source is assessed at 13.9.0, Liquibase Apache source at 4.33.0 and current Liquibase FSL separately. Maintenance/security ownership for an older OSS line is unresolved until implementation dependency selection. Oracle JDBC/Instant Client distribution remains separately licensed; GPL DbGate source is a UX reference rather than assumed Apache-compatible embedded code. Public Bytebase contracts are behavioral research only; no restricted source, gate bypass or UI assets are reused.
- Some consulted local reports/evidence were already uncommitted when the task began. They are linked and preserved, not published or committed by this research. A later explicit publication request must include the required historical evidence or revise those links without rewriting historical findings.

## What local verification establishes

[Validation results](validation-results.json) record catalog/schema consistency, feature/dependency/phase allocation, source hashes and line ranges, selected upstream retrieval when enabled, document links/tables, required diagrams and preservation of pre-existing tracked file contents. [Historical document checks](historical-check-results.json) record the repository's existing research checker.

Legacy fields in the historical checker, such as `odc_deployment_inspected`, `odc_runtime_api_checks` and `changed_existing_files`, describe retained prior evidence; they do not report new deployment inspection, runtime calls or changes by this task.

These checks establish artifact consistency only. They do not execute the proposed platform, validate an Oracle migration, certify licenses, render/test every screen or demonstrate production readiness. The first recommended implementation phase is the separately authorized WP0 disposable-lab feasibility harness in the [roadmap](../PRODUCT-ROADMAP.md).
